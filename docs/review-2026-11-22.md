## Part 1: Using Anonymized Student Projects as Case Studies

### Get an IRB Determination First

Publishing case studies built from student work is human subjects research, because it is a systematic investigation meant to contribute generalizable knowledge. The instructor cannot decide that it is exempt; the IRB office makes that determination.

Two exemption paths are plausible, and one application can cover both:

- **Prospective work** (next semester's course) may qualify under the Common Rule exemption for research on normal educational practices in established educational settings, 45 CFR 46.104(d)(1).
- **Retroactive work** (past projects) may qualify under the exemption for secondary research use of existing records, 46.104(d)(4). It generally requires that identifiers aren't recorded and that you won't contact or re-identify students.

Under FERPA, student work and LMS logs are education records. De-identified records can be used without consent only if all personally identifiable information is removed and a reasonable determination is made that no student can be identified, including by classmates (34 CFR 99.31(b)(1)).

Using your own students' work also creates a power dynamic. The standard remedy is opt-in consent collected by a third party, with the instructor learning who consented only after grades are posted.

### Anonymization Is Harder Than Removing Names

- **Small classes:** classmates can recognize a distinctive project from its description alone.
- **Public repositories:** if a student published the project on GitHub, a distinctive README phrase or project concept is searchable. The name is gone, but the project is findable.
- **Commit histories** contain author emails, usernames, and timestamps.
- **Writing and coding style** are themselves identifying.

Practical remedies: use composite or abstracted cases; report traces as derived features (for example a chart of commit cadence) rather than raw artifacts; and get explicit consent for anything quoted.

### What Finished Projects Can and Can't Measure

GLP needs process data, and most of it was never collected for past projects.

| Component | Computable from existing project data? | Possible source |
|---|---|---|
| Y₁ Temporal Engagement Pattern | Partially | Commit and LMS timestamps; needs a difficulty proxy for each milestone |
| Y₂ Error Trajectory Coherence | Partially | Commit diffs, test-failure sequences, reverts; needs an adjacency matrix built for the assignment |
| Y₃ Cross-Context Transfer | Only if transfer items existed | Exams or assignments with near and far transfer items |
| Y₄ Uncertainty Calibration | No | Requires confidence elicitation that wasn't collected |
| Y₅ Social Knowledge Texture | Yes, if records exist | Discussion posts, reflections, office-hour notes; needs trained coders |
| Y₆ Retrieval Strength Decay | No | Requires designed spaced retrieval with a comparison condition |
| Y₇ Scaffolding Response Curve | No | Requires hint ladders |

So retroactive case studies can demonstrate feasibility for Y₁, Y₂, and Y₅, and possibly Y₃. They cannot validate GLP. The paper should say so explicitly; reviewers will respect the honesty and punish its absence.

### A Better Anchor for the "Borrowed" Class

The preprint's labeled corpus draws on academic integrity cases. That is ethically fraught, since it turns misconduct records into training labels, and it is selection-biased, since it only includes students who were caught.

An alternative: have coding agents complete the same assignments and capture their process traces (commits, timing, error sequences). That gives a known-borrowed anchor without implicating any student. The caveat is that real students using AI are hybrids, so agent traces mark the extreme end of the spectrum, not the typical case.

### Prospective Design for Next Semester

1. Get IRB approval before the term starts.
2. Build the instruments into the course: confidence ratings on quizzes (Y₄), spaced retrieval quizzes (Y₆), hint ladders (Y₇), designed near and far transfer items (Y₃), git-based submissions (Y₁, Y₂), and structured reflections (Y₅).
3. Add an independent criterion: a delayed, proctored, unannounced transfer assessment. This becomes the ground truth that GLP is tested against (see Part 2, step 3).

## Part 2: Converting the Preprint into a Paper

The core diagnosis: the preprint is a framework essay that makes empirical claims without data. Everything below follows from that.

### 1. Decide What Kind of Paper It Is

- **A conceptual measurement framework,** with the claims restated as hypotheses and grounded in assessment theory.
- **An experience report** with case studies demonstrating feasibility.
- **An empirical validation** using prospective data.

Recommendation: combine the first two for the first paper, and save validation for a second paper once next semester's data exists.

### 2. Recast the Claims as Hypotheses

Claims 01 through 03 are empirical. State them as hypotheses, each paired with the test that would confirm or refute it. Claim 04 is a design stance and can stay as written.

Claim 03, that gaming all seven components costs about as much as learning, is the most important claim and the least supported. Agentic tools can manufacture several traces at once: paced typing, plausible error sequences, staggered commits. Gaming costs therefore don't add up independently across components. The traces that resist gaming are the ones collected in controlled contexts, such as unannounced transfer items, proctored spaced retrieval, and live discussion. Much of the robustness comes from where you measure, not from the ensemble itself. Test this directly with a red-team study in which participants, or agents, try to score high on GLP without learning the material.

### 3. Fix the Validation Circularity

In the current design, the "confirmed genuine" class is defined by convergent evidence across the same components the model scores. The labels leak from the features, so the model would validate itself.

The fix is to define ground truth independently: performance on a delayed, proctored, unannounced transfer assessment. The information gain test then becomes a clean question. Does GLP, computed from in-course process data, predict that delayed outcome beyond what artifact quality predicts? That design is methodologically sound, requires no integrity cases, and is exactly what ΔI should measure.

### 4. Cut or Source the Neuroscience

The figures of 2.8-fold BDNF upregulation and a 37% increase in dendritic spine formation have no citation, and I couldn't locate a primary source for either. Much of the BDNF literature comes from exercise and animal studies, and peripheral BDNF in humans doesn't reliably track cognitive change. Learning sciences reviewers are alert to neuromyths, and unsourced molecular numbers will damage the paper's credibility more than anything else in it.

Rewrite Section 3 so the argument rests on behavioral cognitive science, which is strong on its own: desirable difficulties, the testing and spacing effects, the storage-versus-retrieval-strength distinction, and fluency illusions. Neural mechanisms can appear as background, not as the causal link that licenses the measures.

Also soften the line that an AI "cannot produce the behavioral traces those events leave." Traces can be simulated. The defensible claim is about the cost and context of simulating them.

### 5. Add the Missing Literature

The current reference list has six entries. Reviewers will expect at least these:

- **Evidence-Centered Design** (Mislevy, Steinberg, and Almond, 2003): the standard framework for arguing from observable behavior to latent proficiency. GLP is an ECD argument and should be framed as one.
- **Stealth assessment** (Shute, 2011).
- **Detecting "gaming the system" in intelligent tutoring systems** (Baker and colleagues, from 2004 onward).
- **Knowledge tracing** (Corbett and Anderson, 1994).
- **Keystroke logging in writing research** (for example Leijten and Van Waes, 2013, on Inputlog).
- **Metacognitive calibration** and confidence-based assessment.
- **A taxonomy of transfer** (Barnett and Ceci, 2002).
- **Commercial process-capture tools** such as Grammarly Authorship and Turnitin Clarity. Position GLP against them: they document who produced the text, while GLP estimates whether learning occurred.
- **Learning analytics ethics** (Slade and Prinsloo, 2013).

### 6. Tighten the Formalism

- "Credible interval" implies a Bayesian model, and the ensemble described isn't one. Either make Layer 3 genuinely Bayesian, or report calibrated intervals (for example via conformal prediction) and name them accurately.
- Several components need operational definitions: how item difficulty is measured for Y₁, how the adjacency matrix is built for Y₂, and the scale for Y₅ (four φ terms divided by 8 implies each runs 0 to 2, which should be stated).
- Y₄ is defined as a calibration score, but the text refers to a directional version, Y₄_dir, that is never defined.
- Layer 2 needs seven combination models, one per facet, each trained on labeled data that doesn't exist yet.
- For the first paper, a simple, transparent combination (logistic regression, or a pre-registered weighting) is more credible than a three-layer ensemble with no data behind it.

### 7. Align Terminology with the Series

Replace "tier" with "facet" and drop the numbering, so "tier calibration" becomes "facet calibration." That keeps Frictional consistent with how the Irreducibly Human framework is now described.

### 8. Choose a Venue

- **Case studies from code projects with git histories:** the SIGCSE Technical Symposium experience report track, ITiCSE, or Koli Calling.
- **Framework and validation:** Learning Analytics and Knowledge (LAK), the Journal of Learning Analytics, Educational Data Mining (EDM), AIED, or Computers and Education: Artificial Intelligence.

Check current deadlines for each before planning around them.

## Suggested Sequence

1. File one IRB application covering both the retroactive case studies and the prospective course design.
2. **Paper 1:** an experience report presenting a trimmed GLP framework, three to five consented or de-identified case studies measuring Y₁, Y₂, and Y₅ from git histories and reflections, and agent-completed assignments as a contrast condition. Make feasibility claims only.
3. Instrument next semester's course with the full set of components.
4. **Paper 2:** validation against the delayed, proctored transfer criterion, including the information gain test and the red-team gaming study.
